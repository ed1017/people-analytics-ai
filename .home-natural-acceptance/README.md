# Unarmed natural Home acceptance

Exact app source: `3ea509246c13233323a664336b53516599ebd2d7`.
This separate local harness reuses the previously successful one-dispatch build
transport, source inventory, fixed authorization-file protocol, durable receipts,
expiry/wire checks and exact SDK versions. It is not an app release and must not
be merged into the app. No authorization file, reservation, credentials, approval
flags or armed historical manifest is included.

Two user turns only: an arbitrary professional-services objective, followed by
role/horizon clarification and explicit permission to propose editable illustrative
inputs. Both use ordinary Home: no scenario wrapper, conversation-mode header,
example binding, saved goal or accepted plan. `client-request.mjs` extracts and
executes the exact pinned `catalog`, `selectedPlanId`, and `makeRequest` functions
from the application hook. The seed is synthetic ordinary Home evidence, with
18 source entries, no employee records and no verified staffing availability.
The second constructor receives the actual first response state, unmodified.
No old generated answer is used. `browser-provenance.mjs` compares this constructor
against two requests created by typing into the actual Home Page with synthetic
model/data transport. The paid build would execute the extracted constructor and
actual POST, not a browser; hosted UI verification remains a separate task.

The actual app route chooses `gpt-6.1-sol`, medium reasoning and default (Standard)
tier. The transport checks and forwards that payload unchanged. No SWP model
environment overrides are present. The minimal feature configuration is Home
conversation enabled, progress and structured-plans opt-ins off. This matches the
proposed branch-specific Preview flag and does not change persistent settings.

Two turns share at most four generation attempts, zero token-count calls, zero
retries, concurrency one, 5,000 output tokens per call, a conservative 1,050,000
input-token bound, 160,000 payload bytes, 30-second SDK timeout, 90-second route
timeout and 180-second batch timeout. Existing complete source and durable
receipt protections remain. A failed receipt, checked tool, schema, usage or
identity check ends the run. No replacement question or corrective retry is added.
Only clock/evidence and natural demand/revision/staffing calculation tool calls
are allowed by this diagnostic; all database access is refused. The full actual
app tool catalog is transmitted unchanged. No save path is called.

Structural checks replay demand and staffing arithmetic through application
validators and require calculated conditional options after clarification. Human
semantic checks in `fixture.mjs` separately require recommendation-first usefulness,
honest uncertainty, correct literal scope, and claims supported by successful code
results. Passing structure does not automatically pass semantics, prove operational
feasibility, establish independent forecast validation or approve a plan.

`pricing.json` records the 2026-10-09 official pricing check. Standard long-context
rates are $4/M ordinary input, $5/M cache writes and $15/M output. Charging every
input token at the maximum $5/M and retaining a 10% contingency yields:
`4 × (1,050,000 × $5/M + 5,000 × $15/M) × 1.10 = $23.43`.
Retained total is $23.598089; remaining is $26.401911. This is a proposed maximum,
not a reservation or invoice. Recheck pricing and reconcile the ledger before
arming. No token-count call is needed or permitted. A payload-byte cap is not a
tokenizer proof; the full model context-window bound is used for the maximum.

After review, a separately authorized direct child may change only the fixed
`.home-natural-acceptance/run-authorization.json`. It must bind the reviewed local

Node 24.21.0, unique run/reservation UUIDs and a canonical UTC window <= one hour.
The coordinator must separately verify the child's exact SHA/tree and one-file
diff, approval and reservation. Configuration is not permission. Do not arm through
environment variables, reuse an old authorization, or dispatch ambiguously twice.
No such child is prepared here.

The eventual supervised execution route remains one manual Preview create for
the exact armed child, existing credentials/project, no ambiguous retry. Automatic
Git deployment is disabled for both app and diagnostic branches. No new auth,
storage or service is introduced. The local exclusive receipt directory is not
a distributed lock: infrastructure reexecution remains an explicit residual.
Complete receipts are required to close the budget. A successful diagnostic build
emits blank HTML only, not an app deployment. A separate full-app Preview would
verify UI without provider requests after source approval.
