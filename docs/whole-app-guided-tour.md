# Whole-app guided tour

This replaces the planning-only entry popup documented in guided-popup-required-actions.md. Both Home and Introduction launch the actual mounted application in a guided window, not a separate mock dashboard.

## Required staffing journey

The user selected the staffing scenario when asked which historical guide to restore. The popup now opens directly on Scenarios, without the seven-page Overview/Workforce/Future of Work prelude. It keeps the recent required four-step sequence documented in guided-popup-required-actions.md:

1. Press Enter to submit the prefilled fictional 5 FTE / $325,000 prompt (touch Enter key available).
2. Explicitly compare staffing options.
3. Select the prescribed feasible 3-develop / 2-move / 0-hire mix.
4. Review the proposal, then explicitly save the plan and goal.

Only the real browser-local save receipt unlocks the unnumbered continuation: inspect Action plans, open Track this plan, and finish. No progress or achieved outcomes are invented. The original editable three-step planning path outside the forced demo remains unchanged.

Unrelated actions are inert while the tour is active. The current real navigation action is highlighted; the coach and exit remain available. Escape and browser Back/Forward exit guided mode. Each phase resets the window scroll and focuses its heading. Normal use is restored on exit, and the existing exploration isolation protects saved goals and drafts. No external provider calls are needed.

Automated contracts cover ordered routing, save gating, prescribed feasible choice, inline planning, stable child mounting, inert cleanup, and phase focus. Full staged browser acceptance and release evidence are recorded separately.

## Bounded popup correction

The walkthrough is a centered, bounded popup with visible main-page context behind it, including on phones. The background is a noninteractive visual snapshot, not another running app. The fixed example prompt requires an explicit Enter key action; a labelled on-screen Enter key supplies the same action for touch and assistive access. The walkthrough never submits the prompt automatically.

## Direct-entry reliability correction

The demo is local and no longer waits for unrelated Home evidence requests such as survey sentiment. Browser-storage, active-request and editing safeguards remain. The actual sidebar destinations and phone Browse pages control participate in the required-action navigation, so users do not need a hidden alternate route. Phone navigation stays bounded within the popup. Regression acceptance must use actual coordinate clicks on the main entry under slow/failed evidence, and the visible sidebar/mobile navigation.

## Shared planner presentation

The tutorial now uses the normal editable planner component for capacity metrics, assumptions, monthly coverage, tradeoffs, choices and cost breakdown. Guided mode locks those same inputs and permits only the prescribed feasible mix; it is not a separate simplified results screen. Normal mode retains input editing and unrestricted option review. The explicit prompt, comparison, review/save and real Action plans/Track continuation remain required.

Bounded staffing-question paraphrases (for example, "How can we fill our 5 FTE staffing gap on a $325k budget?") offer the same fictional-input review as the original prompt. They never silently accept the example. Different quantities cannot reuse existing calculated results. Questions with additional role/timing context or compound requests stay with the general assistant rather than having that context discarded. This is shared deterministic planning, not a claim that unrestricted live AI reproduces the tutorial.

## Closer normal workflow parity

Normal and guided staffing use the same four-part sequence: review assumptions, explicitly compare, choose a mix, review/save. Accepting or reopening a normal draft no longer silently starts its first comparison. Once compared, explicit edits retain normal reactive recalculation. Normal saving shows receipt-backed confirmation and Action plans/Track continuation. Exiting the walkthrough releases tutorial restrictions so Resume planning scenario opens the same editable draft.

The forced tutorial mix demonstrates a lowest-incremental-cash priority, not a universal recommendation. Users still see the uncovered-work tradeoff and other options. Bounded declarative requests ("I have a 5 FTE gap and a $325k budget. What are my options?") and hyphenated FTE wording share explicit assumption review. In an accepted scenario, bounded cheapest/least-uncovered-work questions reuse current calculations. Extra scope, timing or compound instructions are not stripped to force a demo match.
