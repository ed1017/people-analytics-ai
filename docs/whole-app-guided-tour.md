# Whole-app guided tour

This replaces the planning-only entry popup documented in guided-popup-required-actions.md. Both Home and Introduction launch the actual mounted application in a guided window, not a separate mock dashboard.

## Required journey

1. Overview: inspect the actual snapshot, then open Workforce.
2. Workforce: inspect the baseline, then open Future of Work through Planning steps.
3. Future of Work: inspect the actual Lab, then open Scenarios.
4. Scenarios: explicitly submit the fixed fictional 5 FTE / $325,000 example, compare, select the prescribed feasible 3-develop / 2-move / 0-hire mix, review, and save.
5. Only the real browser-local save receipt unlocks Action plans.
6. Action plans: open Track this plan.
7. Track: inspect the actual saved plan and finish. No progress or achieved outcomes are invented.

Unrelated actions are inert while the tour is active. The current real navigation action is highlighted; the coach and exit remain available. Escape and browser Back/Forward exit guided mode. Each phase resets the window scroll and focuses its heading. Normal use is restored on exit, and the existing exploration isolation protects saved goals and drafts. No external provider calls are needed.

Automated contracts cover ordered routing, save gating, prescribed feasible choice, inline planning, stable child mounting, inert cleanup, and phase focus. Full staged browser acceptance and release evidence are recorded separately.

## Bounded popup correction

The walkthrough is a centered, bounded popup with visible main-page context behind it, including on phones. The background is a noninteractive visual snapshot, not another running app. The fixed example prompt requires an explicit Enter key action; a labelled on-screen Enter key supplies the same action for touch and assistive access. The walkthrough never submits the prompt automatically.

## Direct-entry reliability correction

The demo is local and no longer waits for unrelated Home evidence requests such as survey sentiment. Browser-storage, active-request and editing safeguards remain. The actual sidebar destinations and phone Browse pages control participate in the required-action navigation, so users do not need a hidden alternate route. Phone navigation stays bounded within the popup. Regression acceptance must use actual coordinate clicks on the main entry under slow/failed evidence, and the visible sidebar/mobile navigation.
