# Staffing deadline answer consistency

The hosted source now uses the same explicit delivery-target conflict check for conversational fixed-role summaries as for staffing cards and pin eligibility. Known late active paths are marked not met even when another path has unknown readiness. A cheapest listed-cash option that misses the target is not recommended. Mixed requests with conflicting timing return only the checked comparison and explicitly defer the other questions; materially mixed planning outputs fail closed without persisting the turn. Delivery months and cost-horizon months remain separate; no cash rates, budgets, saved plans, or provider settings are changed.

Offline acceptance covers initial and repeated tool-backed replies, a corrected or removed deadline, equality at the deadline, unknown readiness, and unresolved target provenance. The regression fixture is synthetic, not a live-provider capture. Existing staffing, pinning, budget-period and calendar-routing checks remain part of the focused run. The service and staffing TypeScript graph, position feature type graph, focused ESLint and exact source manifest verification are checked locally. Full restored-runtime build and production verification are separate publication gates. No provider calls or paid tests were used.
