## Final visible flow

- After pinning, one bordered **Action Plans for your goal** card shows preparation status and its disabled creation control. The composer no longer duplicates **Compare workforce options**, its helper, or **Develop a full action plan** / **Draft a goal action plan**. Chat remains available; failed preparation keeps its explicit retry inside the card.
- Compact tabs are **Action Plan #1**, **Action Plan #2**, **Action Plan #3**, for the actual returned count. Plan content, assumptions and **Why these plans** stay visible/inspectable.
- The completed plan's primary action is **Attach Action Plan**. No competing Edit, Discuss, Save, Calculate, develop-mix or Preparation details footer remains.
- Attach opens **Review before attaching**. It does not calculate, save, attach or approve. Missing calculations never disable this entry. The review contains **Review plan fields**, **Review calculation**, **Save draft for later**, explicit calculation/unknown acknowledgements, and **Continue to attachment** (or **Review replacement attachment**). The existing linked-field preview and final confirmation remain authoritative. Cancel closes the review, retaining the working draft. Saving for later saves a draft/calculation only; it does not update attached versions or destinations.
- Required-input failures open the existing editor with the error. Changed inputs invalidate the calculation and acknowledgements by exact input key. A changed goal/evidence context disables attachment and requires explicit preparation; old records remain. Storage errors preserve the existing transaction behavior.
- Describe changes directly in the chat box. A selected current Action Plan registers its bounded edit target locally; explicit change phrasing stages a diff without a model call. Acceptance revises only the working draft. Ordinary questions leave edit review and follow normal chat. Switching plans/goals or changing context invalidates pending previews. No automatic attachment or general-language numeric inference is added.
- For fields outside the chat parser, use **Attach Action Plan → Review plan fields**. The exact ordinary-chat request **Compare workforce options** or **Review workforce numbers** opens the existing explicit capacity/retention scope review for an active pinned goal. It does not request AI, save inputs or calculate. Saved workforce work retains its existing review link.

## Coordinated proposals, not a separate mix button

The normal new-pin/explicit preparation path already requests one AI response containing one to three complete bundles. Instructions now explicitly choose relevant method combinations within those initial proposals, allow a single method, and reject a later combine/develop-mix step or unsupported most-effective/optimal claims. The UI's generic activity-rewrite step is removed. Existing saved proposals are not rewritten, and no per-scenario model call is added. Supporting reasoning and dependencies remain in Why these plans.

Proposal domains remain manager/workload, learning, mobility, compensation, hiring and execution. Investigation goals may receive diagnostic plans; improvement/action goals request proposed delivery or pilot activities. Sparse evidence may yield fewer/no proposals or clarification. Structural validation cannot certify relevance, completeness or live-model instruction compliance. No live response-quality claim is made. Costs and timing remain reviewed assumptions, not inferred effectiveness. Only additional-capacity plans with reviewed inputs can expose **Compare staffing options**, inside the attachment review; this is the existing explicitly run deterministic search, not optimization of intervention effects.

Chat edits retain their bounded dates/duration, existing participant-group, named-expense and component-timing support. Ambiguous budgets and unsupported wording require clarification or structured fields. Success measures, staffing, budget ceilings and component wording are not silently inferred. No payload/schema fields, model-input expansion, new source, database/access/security change, migration, automatic calculation, or operational approval is introduced.
