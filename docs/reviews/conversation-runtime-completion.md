Base: production `b84f164a75cd4bc8b3d1ef702e23ed9df3c2c975`, plus diagnostic-only checkpoint `977fdc02d80a5af2ad19c001e363380a34aad5f9`. This correction is separate from the pilot lifecycle and multi-tab recovery candidates.

The incident was a cumulative 90-second application deadline during the fourth provider attempt, not proof of a particular tool sequence. The runtime now prepares a request-start clock in the supplied browser timezone and an index of the normalized current evidence packet. Scope, observation dates and limitations remain in their authoritative source records. No additional source query or team ranking is introduced.

An optional complete typed final in the same completed provider response as eligible local tools can avoid a subsequent presentation round. A successful candidate alone never completes the turn. Every call runs first. Any feedback, blocking candidate, specialist calculation, projection or progress tool disables this optimization for the remainder of the turn. Final constraint updates, rejections and analysis references require continuation. All referenced candidates must be checked in the current turn against the current constraints. Both ordinary and co-produced finals share one parser and the existing final scope, calculation-reference, constraint, metric and state validation. A final validation failure terminates the request; it is never caught and resumed with partial final-state mutations. Cancellation is checked after tools and before returning state.

Provider instructions require all requested alternatives, domains and decisions to be resolved before emitting completion intent. The runtime does not independently infer semantic completeness from arbitrary prose. Fixtures prove safe execution boundaries for explicit typed outputs; they do not prove real-provider co-occurrence, reliable instruction following, response quality or a latency target. Unresolved or rejected outputs retain the existing bounded continuation/failure behavior.

Diagnostics add at most six tool entries with fixed name/status enums and bounded round/timing counters. Unknown names become `unknown`; no arguments, results, error text, prompts or secrets are included. Deadlines, cancellation, model/tier, token budget and no-retry transport settings are unchanged.
