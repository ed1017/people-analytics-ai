# Home recommendations as Action Plans

The focused restoration asks Home to lead a workforce planning request with at least one actionable proposed Action Plan, checked through the existing `evaluate_candidate` tool. A proposal includes activities, proposed owners, rationale, tradeoffs, a next step and a success-measure approach. Missing population, dates, costs and capacity remain unknown. An unscoped proposal is marked `awaiting-scope`; it is not a calculated result. Ordinary factual questions and explicit discussion requests remain conversational.

Focus is optional. The user can refine a plan, ask for another approach or discuss a combination in chat. Substantive changes use `evaluate_candidate`; parameter-only changes use `revise_parameters`. Exact source IDs/revisions, unrelated assumptions and the original objective are preserved. A chat preference does not save anything. The explicit Choose control saves the reviewed goal and proposal; operational Apply remains separate. Optional questions do not block that deliberate choice.

The active Home catalog does not expose `evaluate_action_plans` or `read_workforce_planning_playbook`. Each evaluation uses the single-candidate tool. The unchanged limits are four model rounds, six operations, 5,000 output tokens per call, four final candidate references and twelve retained working revisions with ancestry guards. Three separate evaluations plus a final response can fit in four rounds when no other tool call is needed. A fourth evaluation needs a later turn; fixtures must not bypass the round limit with an unavailable batch tool. The provider timeout is 60 seconds inside one shared 90-second deadline, with zero retries and a 120-second function limit.

## Verification and unfinished requirements

A real browser run on `f111fed18fdf1dce8b838d5df593ccd02f01fb66` verified one fully specified fictional mentoring pilot: a checked selectable plan with 27 staff hours, explicit Choose with unknowns, and one reload preserving revision 1, its new local goal link and the three existing demo goals. It did not execute operational Apply or a second chat turn. This is acceptance of that scoped restoration path, not broad recommendation quality or sustained latency.

The user's broader multi-option requirement remains unfinished: useful distinct alternatives, conditional comparison/recommendation, optional focus and follow-up combinations still need independent live-model acceptance on generic workforce questions. This release does not guarantee three initial plans or claim live validation of generic turnover advice, four initial options, automatic hybrids or playbook-guided reasoning. Those requirements have not been removed.

Synthetic unit and browser fixtures retain multi-proposal storage, lineage, unknown-resource, calculation, budget, cancellation and explicit-save regressions using the supported single-candidate tool. They can script three proposals in one bounded turn and additional proposals in later turns; that verifies application contracts, not model behavior. Unavailable batch/playbook calls must remain rejected without recording their proposed constraints or data. The [planning reference](swp-reasoning-playbook.md) remains dormant material, not an active model tool.
