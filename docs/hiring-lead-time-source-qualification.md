# Hiring lead-time source qualification — 2026-10-05

## Decision

Retain the existing historical timing summary and the verified synthetic ridge method as **method demonstrations**. The inspected company extract cannot yet support a new company-history fit or a credible backtest of hiring lead time. No score, product prediction, database change or draft PR was produced by this qualification slice.

The model target must remain precise: **days from requisition opening to a recorded actual start, conditional on a completed external fill in one approved role**. Opening-to-accepted-offer is an earlier and distinct event. Productive workforce capacity may begin later than employment start; no capacity-ready date or ramp measure was established. A lead-time estimate for a completed fill does not provide the probability that an arbitrary open requisition will fill or a promised date for an open search.

## Read-only evidence

[Reproduction queries](hiring-lead-time-source-audit.sql) return aggregate counts and metadata only. The existing `ta_requisition_metrics` view supplies final-state recruiting metrics; its accepted-offer date is the earliest accepted `offers.response_date` per requisition. The view includes recorded start dates for filled requisitions but has no label-first-observed time. Its current applicant, interview and offer counts are end-state aggregates, so they cannot be treated as opening-known predictors.

The [verified reference at `9efd7eff`](https://github.com/ed1017/people-analytics-ai/commit/9efd7eff9593c3c2447674b7fa098651ecee931c) already fits a genuine ridge model on **constructed fixtures**: `log1p(opening-to-start days)` from opening-month sine/cosine, with train-only standardization and fixed penalties. It compares the candidate with expanding and recent-window median baselines on aligned cases, separates development selection from final evaluation using an in-process settings lock, and explicitly leaves company-model training, provenance, global untouched-holdout custody, performance and deployment flags false. I reran its three focused ridge/holdout suites: **34/34 tests pass**. This verifies mechanics only. No remote branch code was cherry-picked into this worktree.

The current checkout's existing evaluation contract requires a role-specific all-openings cohort, actual label-first-observed times, dated status history and opening-known feature provenance. Supplying final rows with fabricated observation timestamps would bypass its most important leakage guard. Retrospective completion-only scoring could be described, but it would not qualify a prospective hiring lead-time prediction and would duplicate the verified fixture work without closing this source gap. The user's preference for the latest two years is a window to compare once cohorts are qualified, not proof that any selected role has enough mature events or seasonal coverage.

## Concrete proposed source contract — design only

First check whether the source systems already retain the following fields and history. Capture or expose what is missing through a reviewed internal contract, rather than copying final-state rows into a new prediction table. The names below define semantics; they are **not** executed SQL or a migration.

| Proposed record and fields | Purpose / essential rule |
| --- | --- |
| `hiring_extract_manifest`: `extract_id`, `source_system`, `generator_version`, `source_definition_version`, `population_definition_version`, `extracted_at`, `complete_through`, `role_scope`, `expected_opening_count`, `recorded_opening_count`, `revision_policy`. | Version the synthetic generator and approved role/population; distinguish event completeness from the extract date. A count match is evidence to reconcile, not proof by itself. |
| `requisition_event_history`: stable source requisition key (local audit only), `event_kind`, `event_effective_at`, `source_first_observed_at`, `ingested_at`, `source_revision_id`, `supersedes_revision_id`, job profile/org/location effective at opening, and terminal status reason. | Record approvals/openings, status transitions, cancellations, closures and corrections. Preserve **all** opening cases, including open and cancelled, with their as-known versions. The approved/opened date remains distinct from any later status date. |
| `offer_decision_history`: source offer/application/requisition keys (local audit only), `offer_made_at`, `decision_at`, `decision_status`, `source_first_observed_at`, revision identity. | Distinguish earliest accepted offer from later/superseded offers and from the `hire_date` field. Confirm the business definition of `hire_date` instead of inferring it from equality in this extract. |
| `hire_start_history`: source hire/requisition key (local audit only), `hire_decision_at`, `planned_start_at`, `planned_start_first_observed_at`, `actual_start_at`, `actual_start_first_observed_at`, cancellation/no-show status, revision identity. | Preserve null actual starts and dated changes to plans. The training label becomes eligible only when an actual start was observed by the fold cutoff. Never use a post-opening offer, revised target start or final applicant count as an opening-known feature. |
| Optional `capacity_available_history`: `assignment_effective_at`, FTE/availability and an independently defined ramp or capability measure with first-observed times. | Required only for a **separate** capacity-ready target. Do not substitute accepted-offer, hire or start dates for measured productive capacity. |

For the first approved role, reconcile one row per requisition at opening, all status outcomes, paired accepted-offer and actual-start events, duplicate/missing/corrected labels, and observation time **at each candidate fold cutoff**. Freeze opening cohorts and 12/24/all-history comparisons before inspecting final outcomes; compare the two training-only median baselines with the existing fitted ridge on identical scored cases. Report cohort size, censored/unscored fractions, per-fold MAE and p90 error, and any failed gates. A genuinely untouched recent assessment needs separate custody from this already inspected extract. The existing synthetic reference is ready for that later experiment once the source contract is real and authorized.
