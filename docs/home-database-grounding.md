# Home conversation evidence grounding

The ordinary Home route verifies loaded evidence before constructing the model client. It invokes the existing allowlisted aggregate GET readers locally, under the same request-pinned dataset context, and compares the normalized supplied facts, observation dates, canonical scopes, population labels, source metadata and selected detail/monthly rows. A selected row can be outside the default three-row sample; it must still occur in the current source, with multiplicity preserved. The dashboard's verified filter receipt must match the requested filters. A changed or unavailable loaded source returns 503 before provider dispatch; a stale dataset header returns 409 before the handler runs. Earlier work remains intact and the user must refresh explicitly.

The exact accepted packet remains unchanged, preserving existing proposal/review/save bindings. Server-derived model context includes the dataset token, normalized packet SHA-256, retrieval time, per-source observation date, reader path and source classification. `read_evidence` returns the same provenance. The legacy token `legacy-v1:0` identifies the active routing context, not an immutable certified import. Separate source reads are not one transactional database snapshot. Different source dates remain different; an unknown date is not replaced with retrieval time or September 30.

Only already loaded source groups are reread. Missing sources stay null and unavailable; they are not zero or evidence of absence. Database aggregates, stored scenarios, the separate public BLS reader and fictional/unverified session inputs are explicitly distinguished. Frameworks supply general method only. Owner responsibilities are suggestions, not proof that an actual company role or person exists. All supported staffing/workload/cost arithmetic remains in existing calculators; user/model assumptions remain provisional, visible and correctable. The existing bounded source-scope contradiction check also guards final prose.

This changes no SQL, relation, permission, credential, dataset selector, model policy, tool/round ceiling, retry policy, calculator, saved-plan schema or explicit Choose/Apply boundary. Existing reader implementations continue to own access and suppression; some existing handlers aggregate employee-level records internally. This change consumes their allowlisted aggregate outputs only and adds no raw-record model/tool export. BLS retains its existing separate public-source request. Fresh rereads increase per-turn read work and share the existing 90-second route deadline; not every existing reader cancels its underlying I/O immediately on request cancellation. No automatic retry is introduced.

The live legacy route previously normalized the browser packet without server revalidation. Projection inputs already used fresh reads; the candidate dataset's separate certified provider already has its own rebuild contract. This verifier deliberately accepts only the current legacy provider. It does not select, certify or cut over to the prepared 9,847 dataset.

Offline tests use fictional aggregate responses with the real verifier, request wrapper, service and POST. They cover stale dataset headers, tampered values/dates/rows, duplicate row use, filter mismatch, unavailable sources, missing role readiness, source-date separation, suppression, framework-vs-company namespaces and unsupported scoped assertions. Browser replay uses the real verifier with synthetic aggregate input. These tests are not live database attestation, real-model recommendation acceptance or independent forecast validation. General free-text claims still need semantic review: neither a valid citation nor successful arithmetic proves a causal explanation, feasibility, actual availability or future benefit.
