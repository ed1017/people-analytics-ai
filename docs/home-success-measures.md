# Reviewed success measures in Action Plans

Scope: one optional, goal-bound success measure in the existing local Action Plan draft. The existing Scope editor contains the compact review. The selected plan summary shows the accepted measure, baseline and target separately; Save, Calculate and attachment remain explicit. No DB, API/model-input envelope, forecast or causal-effect changes.

Suggestions are unaccepted prompts, not evidence-based priorities. Turnover, hiring, engagement and skills goals can offer an existing normalized aggregate fact with its source key, company/survey scope and snapshot date. Satisfaction, capacity and other goals receive a useful measure suggestion without substituting a mismatched metric or inventing a baseline. Users must review metric definition, population and period before choosing an observed source. Source values are recorded synthetic context, not proof of a causal mechanism or matching cohort.

User-entered baseline and target values, illustrative assumptions and recorded/adopted baselines retain distinct provenance. Empty values or Unknown remain null; observed zero remains zero. No numerical change, effectiveness percentage, avoided exits or confidence interval is inferred. Targets are intentions, not predictions.

The optional measurement record extends the existing browser-local BundleInputs contract without rewriting earlier version-1 records. Its exact goal and scope snapshot are validated; only user/illustrative targets are allowed. The existing input key and revision mechanisms stale calculations and retain immutable attachments. Changed population/horizon requires renewed measurement review. Comparison also requires matching measurement assumptions. The saved source snapshot remains inspectable if evidence becomes stale; it is not relabelled as current evidence.

Acceptance explicitly changes only the working draft. Goal/plan/evidence changes invalidate pending UI acceptance through the existing context guards and keyed review lifecycle. There is no model call, automatic save, destination update or copied baseline from another goal. Measurement editing currently uses Scope; no new natural-language parser or separate complex form is introduced.

Validation: 943 unit tests; 249 browser assertions (36 success measures, 48 linked attachment, 90 retention/edit, 39 pilot, 36 capacity adoption), all passing. Desktop/mobile/200% reflow cover source-backed/unknown baselines, target provenance, explicit acceptance, save/reload, immutable attachments, stale calculations/evidence and plan/goal switches. Lint, TypeScript and production build pass. Browser APIs are intercepted fixtures; no hosted or live-model acceptance is claimed.
