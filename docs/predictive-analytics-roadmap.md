# Predictive analytics sequence and source gaps

Inspected 2026-10-05, using repository contracts plus [read-only Supabase schema metadata and bounded aggregate hiring checks](predictive-data-inventory.sql) and the [exit qualification](aggregate-exit-qualification.sql). No new records, fields, views, permissions, schema changes or external model inputs were created. Column existence is **not** verification that populated history, completeness or historical availability exists. No person-level employment scoring is proposed.

This sequence favors immediate evidence quality over additional model complexity. It does not require a universal 24/36-month minimum. Appropriate sample size depends on the target, event volume, seasonal cycles, censoring, cohort diversity, forecast horizon and regime changes. Additional synthetic fields can support a richer demonstration but cannot establish real-world validity.

## Recency and structural changes

Turnover has 32 usable monthly observations, not thousands of independent time-series samples merely because many employees exist. Twelve months supplies one annual cycle, 24 supplies two; these are descriptive counts, not adequacy guarantees. This extract has no 2020–2023 turnover series. Hiring starts in late 2023; no 2020–2022 hiring history was found in the opening aggregate inspected here.

The [exit report](aggregate-exit-forecast.md) compares 12/24/all histories on identical temporal origins. Recent mean and seasonal naive have fixed 3/12-month lookbacks and therefore stay unchanged; smoothing is refitted within each window. No new window is chosen from the already-visible July–September assessment. A truly untouched assessment requires a future source/experiment boundary that was not inspected during selection. For hiring, repeat 12/24/all **as-known** training windows on matched opening cohorts after maturity/availability qualification, preserving open/cancelled cases rather than comparing only successful fills. No hiring window-fit experiment is performed in this slice.

A short recent window may adapt to policy, labor-market or organization changes but has fewer events/cycles; longer history may reduce variance while mixing regimes. Use dated known changes and error stability across recent origins to investigate structural breaks; do not infer that older turbulence is irrelevant or that a trend proves an intervention worked. Allow an abstention/baseline result when evidence is weak.

## Reusable interfaces and verified reference

`lib/ml/predictive-evidence.ts` defines **output-only** types for domain/target/unit, source/provenance/exposure, method class, temporal evaluation/custody and uncertainty/calibration evidence. The exit evaluator uses these types now. They do not accept arbitrary features, provide a cross-domain training router, certify metadata declarations, activate other domains or widen an external model boundary. Each later domain retains its own strict source and target contract.

Keep three classes distinct: a fixed historical baseline; a model with parameters fitted from eligible observations; and deterministic arithmetic under user-supplied scenario assumptions. Neither calling a model via an LLM nor calculating a scenario makes its results empirically validated ML.

Remote `cloud-hiring-holdout-verified` was fetched and verified at **`9efd7eff9593c3c2447674b7fa098651ecee931c`**. Its inspected source fits ridge on `log1p(opening-to-start days)` with opening-month sine/cosine only, training-only scaling, fixed penalties and an explicit in-process development/settings-lock/final-evaluation boundary. It is a genuine synthetic numerical estimator with source/holdout limitations explicitly retained. This branch does **not** import, cherry-pick or train that code; its earlier reported tests were not rerun here. It is a verified historical reference for the next isolated hiring workstream, not proof of company-history performance or globally untouched experiment custody.
