# Home assumptions-first scenarios

New supported turnover and explicit additional-capacity plans now carry a local, labeled what-if alongside their existing reviewed budget. This is deterministic arithmetic, not an ML estimate, causal effect or forecast. It adds no model input fields or service requests.

The turnover starting example is a 100-person average workforce, 15% baseline and 12% target over the displayed shared period. Both rates use voluntary exits divided by the same average workforce for that period. Expected counts can be fractional. A capacity example explicitly assumes additional roles are available for the full horizon and shows roles × monthly cost per role × months. It does not establish role/BU scope or availability for the separate staffing planner.

Explicit recognized quantities in the pinned goal take precedence: role counts, planning months, a stated baseline/target rate, a relative reduction and a monthly USD role cost. User values remain user assumptions, not observed facts. Conflicting or ambiguous percentage targets remain unknown. Existing saved drafts, accepted measures, source provenance and capacity mixes are not overwritten with fresh defaults. Company-wide historical/YTD source values are not silently transplanted into a future pilot population or period.

Cost shows an explicitly conditional sum of the listed cash allowances, assuming they are distinct and funded as displayed, plus illustrative role-month cost for the capacity example. Employee time and unentered costs are excluded. This does not replace the existing full-budget result or silently mark overlap/completeness reviews as confirmed. Unknown amounts stay unknown. Funding outside the scope blocks the preview.

Changes use the existing chat, for example `set target turnover to 10%; set average workforce to 200`, `set target additional roles to 4`, or `set monthly cost per role to 7000`. Existing named allowance edits remain available. The user reviews and accepts the proposed diff before changing the draft. Ambiguous spending limits ask a short clarification rather than becoming expenses. Scope changes require an explicit `use this period for the what-if` review; dates and funding are never moved implicitly. No new form or Edit button is introduced.

Attach Action Plan still requires an explicit current calculation and attachment review. The conditional result is saved with that exact draft; old attachments remain immutable and new edits invalidate the prior calculation. The existing additional-capacity planner and deterministic payload are unchanged.

Supported initialization is deliberately narrow: clear turnover/retention goals and explicit additional-role/capacity goals. Replacement-only, combined ambiguous scope, negated scope and other outcome types do not receive an invented effect model. User-stated values outside supported limits require review. Quantities in unrecognized wording are not treated as source-backed facts; visible illustrative assumptions remain proposals for chat review.

Validation on this checkpoint: 1,074 unit tests and 276 browser assertions (48 new what-if journeys, 117 unified attachment, 18 goal clarification, 36 composer, 57 compact layout), lint, standalone TypeScript and production build. The new journey runs for both goal types on desktop, mobile and 200%-equivalent reflow, starts without observed outcome inputs, checks visible conditional numbers, edits via chat, recalculates/attaches without opening a form, confirms old snapshots and reload, and checks clarification/no extra API requests. Synthetic responses are intercepted. Screenshots inspected; no live model test was run. Panel-wide collapse, Apply changes placement and side-by-side comparison are a separate queued UI checkpoint.
