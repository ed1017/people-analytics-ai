# Trend-to-staffing conversation handoff

The two-turn sequence “Which groups are at risk of a capacity gap in the next 3 months?” then “how do i fill the managed service capacity gap?” previously cleared the local trend request before general planning. That discarded its quantitative controls and could yield a generic validation project. Home now asks the mounted trend controller first and returns its local response before any generic provider route. Managed Service and Managed Services resolve to the same verified business-unit code.

The handoff uses the selected or explicitly named group, the current edited/observed trend and projection horizon. Existing per-group staffing assumptions remain separate and are retained. Named group/horizon changes are validated before state changes. Ambiguous groups, unsupported scope/calendar qualifiers, compound edits, conflicting baseline/numeric demand or multiple horizons clarify without mutation. Dataset/context/reset/close boundaries retire the controller; stale dataset callbacks reject reads and changes.

Managed Services has no matched verified workload-demand source. The checked full business-unit partition supplies September 30, 2026 workforce stock, FTE history and January–September departures. The independent Fictional Service Operations/Service Analyst workload example (8 required, 3 productive FTE) is not Managed Services and cannot supply its demand. Neither vacancies nor projected net FTE loss is a measured delivery gap; net changes cannot be converted into gross departures.

The reader can enter productive FTE demand, retain an existing entered demand value, or explicitly choose “Model demand at current recorded FTE”. That changes only the demand assumption. Availability, gross departures, hiring, FTE per hire, arrival lag, productivity ramp and optional cost remain user inputs; missing values stay unknown. No staffing mix, available employees, project labor hours, training/redeployment gains or costs are invented. Existing risk calculation and save/backup schemas remain unchanged. The currently selected projection horizon is carried to the staffing model and its existing save compatibility checks.

Regression tests execute the real parser and transpiled trend/staffing hooks without paid calls: exact aliases, pronouns, ambiguity/scope/time rejection, edited trend and horizon, baseline acceptance, retained entered demand, group switching, no automatic writes, explicit trend save and stale dataset callbacks. Overview AST tests enforce dispatch before clearing the trend or generic transport. Prior continuity/layout/reset tests and the feature TypeScript graph also pass. Desktop/mobile release verification is recorded below after completion. Fresh provider answer quality remains untested; the supported handoff itself is local and deterministic.
