# Saved-plan conversation: bounded first slice

Disabled by default. `NEXT_PUBLIC_HOME_STRUCTURED_PLANS=true` opts in at **build time** for an isolated review build. This change does not set a hosted environment variable, switch the configured model, or enable production. Rebuild without the flag to disable the new composer path and API. Existing chat and explicit plan controls remain available; users in an enabled build can turn off “Discuss saved plans”.

## Contract and authority

The browser's validated decision store supplies the exact active goal, visible saved-plan catalog, selected stable ID, optional comparison selection, immutable drafts and revisions. Legacy originals are projected into a transient catalog; merely asking a question does not migrate or save them. Removed plans remain in history but are excluded from model context. The server validates this supplied snapshot and recomputes results; it has no independent server-side plan database. This is a local planning workflow, not server authentication or verification of workforce facts.

One request uses the existing `CHAT_MODEL`, strict structured output, no tools, no automatic retries, and a 30-second provider timeout. The endpoint accepts at most 460 KB; the validated catalog is already limited to 30 records/450 KB and the model context to 64 KB. No older chat history substitutes for current plans. A response can revise, combine, compare, or ask a focused clarification.

The first revision slice covers an explicit cash ceiling, existing cash allowance, participant group count, shared start month/horizon, hours per participant and coordination hours. IDs must exist. Values must quote complete literals from the current user request verbatim; code parses supported numbers/number words and dates. Partial number words, multipliers, ranges, unsupported units and non-USD currency markers require clarification instead of silently using a smaller quantity or another unit. New missing effort inputs remain unknown. Other saved assumptions retain their existing provenance, including illustrative values. No pilot defaults are generated by this path.

Activity rewrites, population/target changes, additional currencies and coupled staffing revisions are out of scope. Compound requests with unsupported instructions must be clarified as a whole. These semantic decisions still depend on the model; fixture checks do not prove model understanding. Review shows the proposed sources and exact quoted changes before any save.

## Persistence and calculation

Named references must match the exact source ID set. Single-plan comparisons without a number use the selected plan; implicit multi-plan comparisons require an explicit comparison selection. Comparisons render actual immutable plan cards with no save action or model-created totals/rankings. Revisions use the existing calculator; combinations reuse existing overlap reconciliation. Unknown overlap stays unknown. Source cash ceilings and outcome targets are never summed. Known cash-ceiling or activity-date violations prevent saving until reviewed. A combination also blocks if the existing combiner would omit a saved outcome scenario or alter its provenance, including matching illustrative-baseline what-ifs. Historical snapshots remain untouched.

Proposal display is transient. Explicit **Save as new alternative** revalidates the goal, catalog, selection, request identity, revisions and arithmetic, then atomically appends an unapplied, unattached numbered alternative. Originals and attachments are preserved. Request IDs and a proposal fingerprint make identical saves idempotent and reject different outputs under the same ID. Apply and Attach remain separate existing actions.

Goal/context changes, reset, navigation, selection changes (including away and back), catalog reorder/deletion and subsequent requests invalidate pending work. Failed responses preserve the draft and require explicit retry. No generic-chat fallback silently substitutes invented current plans.

## Evaluation and rollout

`tests/home-plan-conversation.test.mjs` has 30 fixed scenarios covering expected model-output contracts, varied wording, ambiguity, explicit selections, deleted/invented references, stale state, duplicate saves, constraints and unknown quantities. `tests/home-plan-conversation-review.test.mjs` adds 54 regressions for complete quantities/units, scenario preservation and exact comparison identities. `tests/browser/home-plan-conversation.mjs` intercepts every evidence/model response and tests desktop, mobile and narrow layouts with preview screenshots. These tests use zero paid model calls and **do not measure real-model interpretation quality**.

Keep this change in a separate draft PR with the flag disabled. Before any enablement, review the fixtures, run approved hosted acceptance and separately authorize any paid language-quality evaluation. Rollback disables the flag and rebuilds; existing saved alternative readers retain the new records and their source history. No database migration, model change, evidence-selection expansion, compensation cutover or FOW work is included.
