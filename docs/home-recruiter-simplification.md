This presentation slice is separate from the synthetic Attrition forecast candidate. It changes no database, authentication, billing, permissions, model input envelope or supported calculator scope. The held eNPS files are excluded.

## Current behavior

- Only the former Home navigation row is labelled Action Planning, with modest emphasis and the same selected state. The separate Planning group, route and Insight to Action header are unchanged.

- General exploration has no Compare workforce options control. A valid active saved goal is required; a stored but unselected goal does not qualify. Click handling rechecks the saved goal synchronously. Switching or deleting a goal invalidates the existing scope review.
- A reviewed structured reply shows a highlighted goal card first. Short explicit outcomes such as `Reduce turnover` retain the user's exact words; open discovery questions retain the reviewed suggested problem. The brief recorded summary uses existing allowlisted facts and identifies scope, missing dates and synthetic provenance. It does not infer causes.
- Pin is the primary action. Evidence, limitations and the associated long reply are collapsed. Optional exploration links derive from validated live finding/question pairs, use source labels, and retain draft and stale-response protections. Invalid metadata produces no links. Ordinary unrelated replies remain expanded.
- Plan #1 / Plan #2 controls are small tabs with selected state, arrow/Home/End keys and a labelled panel. The selected plan is one brief description and seven stacked bullets: Approach, Stakeholders, People needed, Cost, Timeline, Expected outcome and How success is measured. Assumptions follow underneath. Only the Plan selectors are boxed side by side. Individual hypothetical values retain an Illustrative label; an unresolved complete budget is Not yet assessed. There is no separate parallel pilot summary. Proposed diagnostic titles remain diagnostic. Proposed roles are not assigned people.
- The shared comparison caveat appears once. Only current calculations with matching reviewed scope expose numerical tradeoffs. Illustrative assumptions remain visibly labelled underneath the plan; exclusions, completeness, overlap, source evidence and provenance stay in one collapsed Why these plans area. Individual illustrative cost rows are not silently added into a complete budget.
- Guided example instructions describe the current pin-first flow. Starting the example collapses Intro & instructions. Example steps remain collapsed; the example does not approve, calculate, attach or claim AI capability gains.
- The starting guide asks What do you want to achieve? and offers five short common prompts. A skills-specific follow-up permits a mix of training, internal moves and hiring; it is not shown for unrelated goals. The shared helper and composer placeholder describe goals, comparison, plan building/editing and general questions. The composer has a 48px minimum. Home assistant body typography remains 14px/21px. Long replies and drafts remain scrollable and complete.

## Actual calculation coverage and outstanding product gap

The coordinated draft preparation is one existing model response. `reconcileBundle` calculates one explicitly reviewed draft's ledger, dependencies and optional staffing path; it does not enumerate or rank a scenario space. Comparing saved drafts checks matching scope and current input identities. There is no trustworthy scenario-execution count to display on these qualitative cards.

Separately, the existing capacity planner's explicitly run bounded local search varies Build/Move/Buy counts under saved scope and assumptions. Its executed report records `summary.enumerated`, `calculatorInvocations`, complete enumeration, status counts and return filtering. Nondominated candidates describe bounded tradeoffs, not a weighted best or retention effect. This slice does not automatically connect that search to qualitative full-plan generation.

The current generator contract allows zero to three proposals and explicitly permits fewer. Its instructions request coordinated components and at least one delivery/pilot task for improvement goals, but the parser validates shape, references and dependency graphs; it does not establish that generated content is a complete intervention or meaningfully different. Two returned diagnostic proposals therefore do not prove that three integrated solutions were explored. Preserving the explicit outcome at pinning avoids changing an improvement goal into an investigation goal, but it does not by itself solve content quality.

The original pin → efficient scenario search → ranked full plans intent remains incomplete. It requires an explicit reviewed search binding and execution-count contract, supported objective/constraint semantics, and coordinated intervention proposals that can be reconciled against the searched staffing assumptions. Display cleanup does not establish that diagnostic proposals are complete interventions, or that generated prose is semantically reliable. No new claims about retention effects or real-world ML performance are introduced.

## Conversational editing audit

Discuss changes now binds the shared composer to the selected plan, goal, evidence context and revision. Explicit text edits produce a local before/after review; Accept changes into draft calls the existing strict draft revision path. Save and Calculate remain separate. Supported edits cover existing participant counts, named expense amounts/occurrences/funding months, component dates, aggregate population, shared horizon and comparison requirements. Whole requests fail on unsupported or ambiguous clauses. Unknown, zero, illustrative values and user assumptions remain distinct. Plan/goal switches, changed evidence, partial form dates, revised form values and edited request text prevent stale acceptance. No model call or model-input-envelope change is involved.

The local parser accepts everyday phrasing for the selected plan: “start in December 2026”, “move the start to Dec 2026”, “make it three months”, “run the plan for six months”, and “use 20 participants”. Month names require an explicit year. Whole number words from zero through twenty are supported. A single participant group can be inferred from the selected draft; multiple groups require clarification, then “use 20 participants for Engineers” selects the named existing group. These phrases change shared assumptions only: dates on components and expenses do not move automatically, and an inconsistent timeline still needs correction before calculation.

Existing `Set/Change/Update [assumption] to [value]` edits remain available. Optional Please/Can you/Could we wording is accepted. Up to six clauses fit within 1,200 characters, separated by semicolons, newlines or “and” before a supported edit verb. Unknown clears a supported assumption; an Illustrative value prefix retains hypothetical provenance. Every clause must resolve and validate before any preview appears.

“budget20k” and vague total budgets ask whether the user means a plan ceiling or a specific expense amount. Total ceilings remain in the form; named expense amounts retain their displayed cost basis. No total is converted into a per-participant, recurring or other unit cost. Negation, exceptions, approximate values and requests referring to multiple plans are rejected with clarification rather than partly applied. Users can select Discuss changes on the intended plan and restate their request.

This remains a bounded deterministic parser. Arbitrary wording, relative dates, staffing mixes, budget ceilings, deadlines, adding/removing components and freeform plan wording use the working form. There is no new AI extractor, model request or transmitted context. The reviewed diff, explicit acceptance, provenance, calculation/save steps and saved versions remain in place. Changed plan, goal, scope or evidence invalidates the active review. Restoring a previous scope cannot re-enable an old review; Discuss changes starts a fresh one.

## Attach and linked planning audit

Home now opens one attachment review from **Attach plan to goal**. It previews compatible reviewed Development quote inputs and existing added-capacity inputs. Empty compatible fields can default to Fill empty; nonempty unrelated fields default to Preserve. Confirm attachment saves the draft/calculation, immutable attachment, chosen destination changes, existing application receipt and context transition in one local storage transaction. Cancel, stale state, unsupported selections or storage failure publish none of that transaction. No model request or destination calculation runs as part of attachment.

The original proposal/attachment source fingerprint stays immutable. Each transition records the physical context before and after its own application, the preparation timestamp, destination snapshots and receipt-owned fields. Current evidence is projected through both recorded snapshots to verify that only the reviewed application explains the changed source context. A successful self-application remains current after reload. Changes to the goal, external evidence, quote identity, unlinked inputs or earlier history invalidate this reconciliation. A new explicit preparation starts a new ownership generation.

After an accepted draft revision is explicitly calculated and reviewed, Save opens the same linked-field review. A field defaults to Replace only when its current value still equals the last receipt-written value and its plan, preparation, signature and source mapping match. A manually changed linked field defaults to Preserve and shows a conflict; replacing it requires an explicit choice. Unknown source values never clear known destination values. Previous attachments, receipts and workforce versions remain available. Saving a draft with a stale calculation saves only that working draft; it does not update destinations.

Coverage remains bounded: existing compatible Development options and added-capacity inputs only. Source headcount and catalogue-scenario selection are read-only. The flow does not create provider quotes, populate unsupported Finance/execution buckets, perform retention modeling or claim that all Planning buckets are synchronized. With no compatible destination, the user can explicitly attach with zero planning-field changes. Destination calculations remain explicit. The existing separate application component is retained for older isolated callers; ordinary Home exposes only the unified review.
