# Fictional Future of Work arrival

This bounded slice adds an opt-in service-ticket illustration to the existing unconfigured Future of Work page. It does not activate workforce task data. Editable scope, month-end opening, 1-6 months, volume, effort, exposure, potential saving, adoption, realization and potentially reassignable share are explicit assumptions.

Default monthly stages are 1,600 baseline hours, 640 exposed, 320 potential saving, 160 after adoption, 128 after assumed realization and 64 potentially reassignable hours. The stages overlap and must not be added together. Confirmed staffing release is unknown. Fixed illustrative supply is 10 people / 10 FTE, 160 productive hours per FTE, 100% allocation and no movements. No job losses, automatic cost savings, skill-match proof or measured results are inferred.

The handoff is separately reviewed and checks current inputs, dataset/goal and current scenario before acceptance. Any non-default unsaved scenario requires explicit replacement acknowledgement. Cancel leaves it intact. The draft uses remaining effort (0.92 hours/item by default, conservatively rounded upward), zero productivity uplift and unknown cost rate. It remains unconfirmed until the existing Scenarios confirmation/calculation flow. Saved scenarios are never overwritten.

An optional bounded sourceNote travels through the existing capacity draft, record and chat-context readers; older drafts retain their exact contract. The origin note records original dates, volume and percentage assumptions and is displayed on reopening. It is provenance, not a second calculation; later scenario edits remain independent.

Validation: focused deterministic tests cover formula stages/zero values, invalid and missing assumptions, stale handoff rejection, record/chat compatibility and an existing save/reopen transaction. tests/manual/future-work.browser.mjs checks linked slider/number inputs, blanks, explicit handoff, cancellation preserving a 0.95-hour draft, replacement, calculation, local save and reload at desktop/phone widths. Its isolated fictional goal fixture and request routing block all AI, writes and external traffic. FUTURE_BASE_URL selects local or production; FUTURE_FIXTURES optionally supplies captured public synthetic responses; FUTURE_OUTPUT_DIR stores local screenshots. No credentials, database changes or population rollout.
