# Local integrated plan review and staffing search

## Code-level audit

- `components/pages/overall-overview-page.tsx` retains the user's pinned goal and passes the pin event into `HomeSolutionBundles`. `components/home-solution-bundles.tsx` calls `createHomeBundlePreparation` with `new-pin`, through one existing `/api/chat` request. `lib/home-bundle-preparation.ts` handles explicit retries, stale context, validation and local persistence.
- `app/api/chat/route.ts` uses `buildHomeBundleFormat` and `homeBundleInstructions` for that preparation. `lib/home-solution-bundles.ts` permits zero to three bundles, with one to six components each. Validation covers exact goal, shape, text limits, source references and dependency graphs. It does not establish intervention completeness, causal support or meaningful diversity. Two diagnostic proposals can pass despite instructions requesting delivery for improvement goals. No third option is required.
- `lib/home-bundle-reconciliation.ts::reconcileBundle` evaluates one explicitly calculated draft. Dependency dates gate readiness. Reviewed groups and memberships determine unique participants, with overlap left unknown unless resolved. A shared cost source enters the ledger once, allocations preserve totals, and employee time stays separate from cash. Unknown inputs or incomplete reviews keep the complete budget unknown. An optional capacity path calls `calculateWorkforceIncrement`; this does not enumerate alternative combinations.
- `lib/workforce-mix-search-core.ts` already performs deterministic bounded Build/Move/Buy enumeration. It requires a current saved calculation and matching evidence, preserves the reviewed path totals/timing, invokes the calculator per candidate plus a reference, and records exact counts. It distinguishes met, not-met, unknown and invalid outcomes. Nondominance considers cash, separate employee-time value, added employees and conditional coverage month among comparable candidates. Results are ordered by Build/Move/Buy, not a weighted quality ranking. The evaluation cap is 1,000 calls and output cap is 64.

## Implemented local increment

`lib/home-plan-integration.ts` and `components/home-plan-integration.tsx` connect two explicit actions to each current Home draft, inside one expandable review area.

**Delivery mix review:** The user can preview concrete proposed activities for methods already present in the selected bundle. Local templates cover manager/workload practices, learning and supervised practice, voluntary mobility, compensation proposals, hiring/onboarding, and delivery evaluation. At least two distinct non-execution methods must already exist; repeated methods require review rather than automatic merging. The review shows prior and proposed activity text, existing references, proposed roles and prerequisites. Explicit acceptance revises the working bundle using the existing strict proposal revision path. Goal wording, component IDs, evidence, owners, dependencies, quantities, dates, staffing inputs and cost/group links remain intact. The change resets dependency, cost-completeness and comparison confirmations and invalidates old calculations. Save and Calculate remain explicit. No source is claimed to prove intervention effectiveness.

**Staffing search:** A current draft must confirm additional capacity and comparison scope, use reviewed staffing assumptions, and exactly match the saved workforce calculation's goal, inputs, role, business unit, demand and horizon. Otherwise the UI explains the missing review or mismatch. When eligible, the component reuses `WorkforceAlternatives` and `WorkforceLocalSearch`, including existing candidate review, verification and explicit saving. Bounds start unconfirmed. Preflight counts are labelled planned enumeration, not executed results. Executed, constraint-matching, failed, unknown, invalid and calculator-call counts appear only after the local worker returns. Changing the draft/context or accepting a revised delivery mix removes the prior transient search review.

## Remaining product gaps

- Local delivery templates improve proposed activities, but do not certify that a plan is complete, appropriate or operationally feasible. Measures/baselines, relevance, resources, dates, funding and approvals still require review. Model preparation can still return diagnostic or insufficiently distinct proposals.
- Search covers staffing counts under fixed reviewed cost and timing assumptions. It does not optimize training design, compensation policy, management practices or combined intervention effects.
- Selected staffing alternatives use the existing reviewed alternative workflow. They are not automatically rewritten into a complete bundle: affected flow/group mappings, dependencies and shared costs need explicit reconciliation before that adoption can be safe.
- Full-bundle costs and dependency-gated readiness may differ from the staffing calculator's narrower tradeoffs. Staffing results are labelled accordingly and never promoted as a full-plan ranking.
- Retention plans without a validated response model remain proposed intervention mixes. There is no predicted optimum, invented execution count, numerical causal effect or forced third plan.

No model request per combination, new model payload fields, live model calls, database changes or external mutations are introduced.

The 256 browser assertions comprise 27 full Home integration checks, 64 existing search-worker checks, 72 conversational-edit checks, 45 attachment/update checks and 48 bundle calculation/history checks. Full Home cases cover desktop, mobile and 200% reflow; the isolated worker harness covers desktop/mobile and cancellation, stale sources, caps, unavailable workers and exact Node/worker report agreement. Its React alias prevents duplicate React copies in this cloud dependency layout.

The Home fixture returns two proposals and confirms that delivery review preserves that count. It verifies planned versus executed counts, exact constraint-match counts, explicit acceptance/save/reload, retained earlier drafts, unchanged workforce versions, preserved participant/cost entries and renewed review gates after a proposal change. All service responses are intercepted synthetic fixtures. No live model request, push, PR update, merge or deployment was performed.
